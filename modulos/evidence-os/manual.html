Manual de Usuario

¿Qué hace este módulo?

Empaqueta cualquier archivo o texto en un paquete .evidence verificable: hash SHA-256 + HMAC + firma Ed25519 + sello temporal. Prueba de existencia, autoría e integridad.

¿Cómo se usa?

  • Ejecuta primero 2.1 (Humano), 2.2 (IA) y 2.3 (Gobernanza).
  • Abre modulos/evidence-os/index.html.
  • Escribe tu contraseña maestra.
  • Elige tipo de evidencia y modo (texto o archivo).
  • Aporta el contenido y la declaración de autoría.
  • Toca "Sellar paquete .evidence".
  • Descarga el archivo .evidence.

Verificación independiente

  • Cualquier persona con el archivo .evidence puede verificar integridad.
  • Sube el archivo en la sección "Verificar".
  • Si necesitas verificar el contenido exacto, pega el texto original también.

Manual de Admin

Integración

import { EvidenceOS } from './evidence.js';

const evidence = new EvidenceOS(core, storage);

const paquete = await evidence.sellar({
  contenidoBytes, nombreArchivo, tipoMime,
  tipo, declaracion, notas,
  humano, pactoIA, gobernanza
});

const ok = await evidence.verificar(paquete);
const okContenido = await evidence.verificarConContenido(paquete, bytes);
const blob = evidence.exportarEvidence(paquete);

Estructura del paquete .evidence

CampoDescripción
id_evidenciaID único tipo EV-XXXXXXXX
hash_sha256Hash del contenido binario
hmac_sha256HMAC con huella del humano como clave
payload_hashHash del payload canónico
firma_ed25519Firma del humano sobre payload_hash
sello_temporalObjeto NOM-151

Persistencia

Los paquetes se cifran con Cripto Core y se indexan en Storage Dexie bajo el tipo 'evidence'.

Manual de Seguridad

Modelo de amenazas

  • Alteración del contenido: el hash cambia si alguien modifica el archivo.
  • Suplantación del firmante: la firma Ed25519 requiere la clave privada del humano.
  • Manipulación del paquete: el payload_hash detecta cualquier cambio en metadatos.
  • Replay de HMAC: el HMAC usa la huella del humano como clave, única por identidad.

Parámetros criptográficos

  • SHA-256 para hash del contenido y payload.
  • HMAC-SHA256 con clave derivada de la huella del humano.
  • Ed25519 para firma del humano sobre el payload_hash.
  • Sello temporal NOM-151 con referencia a QTSA Firmaprofesional B02.

Limitaciones honestas

  • El sello temporal es local-first: para validez legal plena requiere anclaje en blockchain o QTSA externa (módulo 1.3 facilita el anclaje).
  • El HMAC usa la huella del humano como clave, lo cual es público si el humano compartió su huella. Para mayor seguridad se recomienda derivar una clave secreta separada (futuro módulo).
  • No hay validación de originalidad del contenido: prueba que el contenido existía y fue firmado, no que fuera original.
  • Este módulo NO reemplaza a un notario ni a un QTSA cualificado para efectos legales plenos.
