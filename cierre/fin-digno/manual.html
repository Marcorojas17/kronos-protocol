Manual de Usuario

¿Qué hace este módulo?

Cierra el legado con dignidad: escribe la carta final, acepta los criterios de fin y sella una cláusula de resurrección firmada con Ed25519.

¿Cómo se usa?

  • Ejecuta primero todos los módulos previos (2.x, 3.x, 4.x, 5.x, 6.1).
  • Abre cierre/fin-digno/index.html.
  • Escribe la contraseña maestra.
  • Lee los criterios de fin y marca los opcionales que apliquen.
  • Escribe tu carta final al usuario (mín. 50 caracteres).
  • Selecciona el motivo del cierre.
  • Toca "Sellar cierre del legado".
  • Descarga el certificado y exporta el .legado final.

Sobre la carta final

Puede ser a tu yo futuro, a un heredero, o a quien encuentre este archivo en 2099. Escríbela como si fuera la última. Porque lo es.

Manual de Admin

Integración

import { FinDigno } from './fin.js';

const fin = new FinDigno(core, storage);
const cert = await fin.sellar(
  { carta, motivo, sucesor, cartaFirmada },
  humano, pactoIA
);
const ok = await fin.verificar(cert, humano, pactoIA);
const resurreccionOk = await fin.verificarResurreccion(cert, humano, pactoIA);

Cláusula de resurrección

Hash determinista derivado de: fundador + huella + IA + fecha de cierre. Permite verificar que un cierre es auténtico y que el legado puede ser reconstruido con la misma contraseña y el paquete .legado completo.

Criterios de fin

  • Exportación completa del .legado (obligatorio).
  • Rituales de las últimas 4 semanas ejecutados (obligatorio).
  • Sucesor designado (opcional).
  • Carta final escrita (opcional).
  • Aceptación de la cláusula de resurrección (obligatorio).

Manual de Seguridad

Modelo de amenazas

  • Cierre alterado: el hash_cierre lo detecta.
  • Suplantación del fundador: la firma Ed25519 lo impide.
  • Falsa resurrección: la cláusula se recomputa y compara.

Parámetros criptográficos

  • SHA-256 para hash del payload y de la cláusula.
  • Ed25519 para firma del fundador.
  • AES-GCM-256 heredado para persistencia cifrada.

Limitaciones honestas

  • El cierre es simbólico y verificable, pero no bloquea el ecosistema: puedes seguir usándolo después de cerrar. Es una declaración, no una destrucción.
  • La resurrección requiere la misma contraseña y el mismo paquete .legado. Sin ambos, es irrecuperable.
  • La carta final se guarda cifrada dentro del ecosistema. Si quieres que sea pública, debes exportarla y publicarla tú.
  • NO destruye datos: es un acto simbólico con consecuencias verificables, no un borrado criptográfico.
