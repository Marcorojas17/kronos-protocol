```text
┌─[ 01 ]──────────────────── TIPOS DE CONTRIBUCIÓN ─┐
│                                                     │
└─────────────────────────────────────────────────────┘
```

✅ Bienvenidas

· Corrección de errores tipográficos en documentación
· Mejoras de redacción en textos del Movimiento
· Traducciones a otros idiomas (inglés, portugués, francés)
· Corrección de bugs en el código
· Mejoras de accesibilidad (a11y)
· Mejoras de rendimiento
· Documentación técnica adicional

⚠️ Requieren discusión previa

· Nuevas funcionalidades — abrir issue primero
· Cambios arquitectónicos — abrir discussion primero
· Cambios en los 6 principios — solo con aprobación de 2/3 de fundadores Génesis
· Cambios en licencias — requiere consenso

❌ No aceptadas

· Cambios que violen los 6 principios
· Uso comercial no autorizado
· Añadir dependencias con licencias incompatibles
· Cambios en el tono editorial sin justificación
· Spam o autopromoción

---

```text
┌─[ 02 ]───────────────────── PROCESO PASO A PASO ─┐
│                                                    │
└────────────────────────────────────────────────────┘
```

Paso 1 — Fork del repositorio

```bash
git clone https://github.com/Marcorojas17/kronos-protocol.git
cd kronos-protocol
```

Paso 2 — Crear una rama

```bash
git checkout -b feature/nombre-descriptivo
```

Prefijos sugeridos:

· feature/ — nueva funcionalidad
· fix/ — corrección de bug
· docs/ — documentación
· style/ — formato/estilo
· refactor/ — refactorización

Paso 3 — Hacer los cambios

· Un cambio por PR
· Mensajes de commit descriptivos
· Seguir el estilo del código existente

Paso 4 — Commit

Formato sugerido:

```
tipo: descripción corta

Cuerpo opcional con más detalle.

Refs: #123
```

Ejemplos:

```
docs: corregir typo en manifiesto.md
fix: enlace roto en movimiento/index.html
feature: añadir sección FAQ al manifiesto
```

Paso 5 — Push y Pull Request

```bash
git push origin feature/nombre-descriptivo
```

Abrir PR contra main.

Cada PR es revisado por el mantenedor. Criterios de aceptación:

1. Alineación con los 6 principios
2. Calidad técnica
3. Calidad de redacción
4. No introduce problemas de seguridad
5. No añade dependencias innecesarias

Tiempo de respuesta: 7-14 días hábiles.
