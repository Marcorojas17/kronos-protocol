Manual de Usuario

¿Qué hace este módulo?

Define roles y asigna permisos a identidades selladas (humanas o IA). Cada asignación se firma criptográficamente con la llave del fundador. Es la capa de gobernanza del ecosistema.

Roles disponibles

  • Fundador: control total del protocolo.
  • Co-autora IA: firma junto al fundador, no modifica política.
  • Colaborador: crea y firma registros, no ancla.
  • Testigo: verifica, no modifica.
  • Auditor: lee todo, exporta legado, no modifica.
  • Ciudadano: crea su propio registro, verifica otros.

¿Cómo se usa?

  • Escribe tu contraseña maestra.
  • Pega el hash de la identidad (del Registro Humano o IA).
  • Escribe el nombre y selecciona el tipo.
  • Elige el rol a asignar.
  • Toca "Asignar rol".
  • Recibirás un certificado firmado con la lista de permisos.

Manual de Admin

Integración

import { CriptoCore } from '../../cimiento/cripto-core/core.js';
import { StorageDexie } from '../../cimiento/storage-dexie/storage-v2.js';
import { Permisos } from './permisos.js';
import { RolesPermisos } from './roles.js';

const core = new CriptoCore();
await core.init(password);
const storage = new StorageDexie(core);
await storage.init();

const permisos = new Permisos();
const roles = new RolesPermisos(core, storage, permisos);
await roles.init();

// Asignar rol
const asig = await roles.asignar({
  identidad_hash: 'abc123...',
  identidad_nombre: 'Marco A. Rojas V.',
  identidad_tipo: 'humano',
  rol: 'Fundador'
});

// Comprobar permiso
const puede = await roles.puede('abc123...', 'anclar_ethereum');
// → true

Base de datos

  • Nombre Dexie: kronos-roles
  • Tabla: asignaciones
  • Índices: ++id, identidad_hash, identidad_tipo, rol, timestamp, activo

Manual de Seguridad

Modelo de confianza

  • Cada asignación se firma con la llave Ed25519 del fundador.
  • El hash del payload detecta cualquier alteración posterior.
  • La matriz de permisos es declarativa y auditable.
  • Las asignaciones pueden revocarse sin eliminar el historial.

Limitaciones honestas

  • La matriz es una declaración, no un sandbox técnico.
  • Si alguien obtiene acceso a la llave del fundador, puede falsificar asignaciones.
  • La verificación de permisos opera a nivel de aplicación.
