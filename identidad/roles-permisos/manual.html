Manual de Usuario

¿Qué hace este módulo?

Define la matriz de gobernanza: 5 roles × 20 permisos. Firmada con Ed25519, vinculada a tu identidad humana y al pacto IA.

¿Cómo se usa?

  • Ejecuta primero los módulos 2.1 (Humano) y 2.2 (IA).
  • Abre identidad/roles-permisos/index.html.
  • Escribe la misma contraseña maestra.
  • Marca los permisos de cada rol en la tabla.
  • Elige política y caducidad.
  • Toca "Sellar gobernanza" y descarga el certificado.

Roles canónicos

  • Fundador: todos los permisos. Autoridad máxima.
  • Guardián: audita, verifica y puede proponer cambios.
  • Creador: registra y firma obras.
  • Colaborador: aporta sin privilegios de firma.
  • IA Co-autora: asiste y estructura, sin propiedad.

Manual de Admin

Integración

import { RolesPermisos } from './roles.js';

const roles = new RolesPermisos(core, storage);
const cert = await roles.sellar(
  { politica, caducidad },
  humano, pactoIA
);

const puede = await roles.tienePermiso('creador', 'firmar_registro');
const ok = await roles.verificar(cert, humano, pactoIA);

Modificar la matriz por defecto

Los arrays ROLES, PERMISOS y matriz viven en roles.js. Edita allí y vuelve a sellar para reflejar los cambios.

Validaciones automáticas

  • El rol Fundador debe tener todos los permisos.
  • Deben existir las identidades 2.1 y 2.2 previas.
  • La firma dual requiere que humano e IA coincidan con los certificados previos.

Manual de Seguridad

Modelo de amenazas

  • Escalado de privilegios: la matriz firmada no puede editarse sin romper el hash.
  • IA maliciosa: la firma dual requiere que la IA esté vinculada al humano.
  • Suplantación de rol: cada certificado está firmado por el humano con Ed25519.
  • Alteración de política: cualquier cambio en el payload rompe el hash.

Parámetros criptográficos

  • SHA-256 para hash de matriz y firma dual.
  • Ed25519 para firma del humano sobre la matriz.
  • AES-GCM-256 heredado para persistencia.

Limitaciones honestas

  • La gobernanza es local: no hay servidor que valide la matriz por ti. Cada módulo consumidor debe verificar el certificado.
  • No hay revocación automática: si cambias la matriz, debes volver a sellar.
  • La política "delegada" permite a guardianes elevar roles, lo que relaja la seguridad. Elige "estricta" si prefieres control total.
