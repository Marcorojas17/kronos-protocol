Manual de Usuario

¿Qué hace este módulo?

Capa de persistencia estructurada versionada. Guarda, lista, filtra, cuenta y exporta registros cifrados.

¿Cómo se usa?

  • Abre cimiento/storage-dexie/index.html.
  • Escribe la contraseña maestra.
  • Escribe contenido y elige tipo.
  • Toca "Guardar registro".
  • Lista, filtra o exporta según necesites.

¿Qué evitar?

  • No pierdas la contraseña maestra: sin ella, los datos son ilegibles.
  • No exportes el .json a lugares públicos sin cifrar (contiene bloques cifrados, pero igual).

Manual de Admin

Integración

import { CriptoCore } from '../cripto-core/core.js';
import { StorageDexie } from './storage.js';

const core = new CriptoCore();
await core.init(password);

const storage = new StorageDexie(core);
await storage.init();
await storage.guardar('nota', { texto: 'hola' });
const todos = await storage.listar();

Versionado y migraciones

  • v1: registros + meta.
  • v2: añade estado a registros + tabla migraciones.
  • Para añadir v3: agregar bloque .version(3).stores().upgrade().

Backup

Toca "Exportar .json" en la demo. El archivo contiene bloques cifrados + metadatos. Importable con storage.importar(json).

Manual de Seguridad

Modelo de amenazas

  • Robo de IndexedDB: los registros están cifrados con AES-GCM-256.
  • Alteración directa: el hash chain del Cripto Core detecta cualquier cambio.
  • Falsificación: cada registro lleva firma Ed25519 verificable.
  • MITM: no hay red, todo local.

Parámetros heredados del Cripto Core

  • PBKDF2 · SHA-256 · 600k iteraciones · salt 32B.
  • AES-GCM-256 · IV 12B por bloque.
  • Ed25519 · par persistente.

Limitaciones honestas

  • Dexie guarda bloques cifrados, pero los índices (tipo, timestamp, hash) son visibles.
  • Un XSS podría intentar leer IndexedDB: la CSP estricta en Capa 5 mitiga.
  • No hay anclaje blockchain todavía (módulo 1.3 lo hará).
